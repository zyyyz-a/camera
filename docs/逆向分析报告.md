## 0. 一句话结论

这个"影视飓风相机安卓版"**不是影视飓风自研的相机 App**,而是 **Blackmagic Camera 官方 APK 的二次打包改名版**:包名、类结构、原生库、内置 LUT 全部是 Blackmagic Design 的资产,只有 `app_name` 被改成"飓风相机"、并用一张国内自签证书(`CN=np, L=南京`)重签后由第三方下载站分发。

影视飓风官方的「飓风相机」只有 iOS 版,安卓侧不存在同名官方产物。**装这个包 = 装了一个来源不明的重签应用**,功能上和官方 Blackmagic Camera 一样,但签名链、更新链、信任链全部被第三方接管。

## 2. 证据链:为什么判定是 Blackmagic Camera 重打包

**E1 — 包名与入口类原样保留**
`com.blackmagicdesign.android.blackmagiccam`、Application 类 `BmcApp`、`MainActivity`,与 Blackmagic Design 官方 Android 版完全一致。改包者没有动类名(动了就要重写 manifest + 全量重打包引用)。

**E2 — 应用名字符串是唯一被改的资源**
`aapt2 dump resources` 全表扫描,含"飓风"的条目只有 4 条,全部是 `string/app_name`(默认配置 + zh 配置各两条):

```
resource 0x7f11005c string/app_name
  () "飓风相机"
  (zh) "飓风相机"
```

全 APK 980 个文件里,中文关键词"影视飓风""飓风"在 DEX 中**零命中**——代码层没有做过任何品牌改写,只在资源表改了名字。

**E3 — 内置 Blackmagic 官方创意 LUT**
`assets/bmc_luts/` 41 个 `.obj` 文件,四套色彩空间目录,文件名与 BMD 官方 App 内置 LUT 完全对应:

```
Cinema Teal  Day Night  Dusty  Monochrome  Nature
Nostalgic    Paloma     Rift   Vivid       Warm Fade   Neutral Rec. 709
```

`assets/luts/` 下另有 `rec709_luminance_lut_33.obj`、`p3d65_luminance_lut_33.obj`、`hlg_luminance_lut_33.obj`——BMD 的亮度 LUT 集。

**E4 — 原生层全是 BMD 组件**
```
libdavcloudclient.so        14.1 MB   DaVinci Resolve Cloud 客户端
libgstreamer_android.so     26.5 MB   GStreamer 多媒体管线
libOne.so                    8.9 MB   Insta360 one-camera SDK 主体
liblutparser.so             42 KB     .cube LUT 解析(JNI)
libbmddavcloudclient.so    259 KB     BMD 云客户端封装
libdavstream.so / libdavstreamd.so    推流
libtentacle-lib.so / libbmd-tentacle-lib.so   Tentacle 同步/时码
libnativeplayer.so / libbmdaudio.so / libinsbase2.so
```

**E5 — 相机控制协议是 BMD 私有协议**
APK 根目录直接躺着 `.proto` 源文件:

```
camera_control.proto   package bmd.cam_app_control.v5;
                       message AppInfo { string name = 1; // "Blackmagic Cam" ... }
```

字段里有 `CamWhiteBalanceRangeProperty`、`CamSensitivityRangeProperty`、`PROPERTY_ID_SLATE`、`reel/scene/take` 场记板字段——这是 Blackmagic 相机遥控协议的 v5 版本,不是通用 Camera2 封装。

**E6 — 签名主体是个人自签,不是 Blackmagic Design**
官方签名主体应为 `Blackmagic Design`;样本为 `CN=np, OU=np, O=np, L=南京, ST=江苏`——典型的一键生成 keystore 默认填充(`np` = not provided)。同时 v1/v2 签名缺失、只有 v3,也是 apktool + apksigner 重打包的典型指纹。

**E7 — 图标不是 BMD 官方图标**
`res/mipmap-*/ic_launcher.webp` 是一张通用蓝色相机图标,与官方 Blackmagic Camera 的深色环形镜头图标不一致,属于换皮素材。

**E8 — META-INF 保留了原始 JAR 清单但已失效**
`META-INF/MANIFEST.MF`(124 KB)、`CERT.SF`、`CERT.RSA` 仍在,但 `apksigner` 判定 v1 签名无效——原包 JAR 签名被破坏后重新用 v3 签名覆盖,`CERT.RSA` 里是新的自签证书。

> 结论:改动面 = `string/app_name` + 图标 + 重签名。**代码、资源主体、原生库、协议、LUT 全是原厂资产。**

### 3.1 R8 混淆与类名还原(release 构建实证)

DEX 经过 R8 full-mode 处理,多数业务主类被改名成单字母短名,但**协程 lambda 内部类保留了原始包路径和类名**。用内部类的 `this$0` 字段类型反查,即可还原主类:

```
Lcom/.../settings/LutManager$importLuts$2$1$1.this$0:Lcom/blackmagicdesign/android/settings/c;
Lcom/.../settings/SettingsManager$setLut$1.this$0:Lcom/blackmagicdesign/android/settings/r;
```

| 原始类 | R8 后短名 | 证据 |
|---|---|---|
| `com.blackmagicdesign.android.settings.LutManager` | `com.blackmagicdesign.android.settings.c` | 15 个内部类 `this$0` 一致 |
| `com.blackmagicdesign.android.settings.SettingsManager` | `com.blackmagicdesign.android.settings.r` | 46 个内部类 `this$0` 一致 |
| `LutsRepository` / `AuthenticationManager` | 同类推导(`settings.*` / `cloud.manager.*` 单字母) | 内部类 `$getLuts$2`、`$login$1` 等可反查 |

**实操含义**:写 Frida 脚本时按原类名 hook 会静默失败,必须走短名,或者干脆锚定保留原名的协程内部类(`...$importLuts$2.invokeSuspend`)。`frida_bmc.js` 里已经两条路都埋了。

## 6. LUT 管线

```
用户导入 .cube → LutManager.importLuts
                → NativeLutParser.parseCubeFile(String path, int)   // JNI: liblutparser.so
                → Lut(fileName, description, is1d, is3d, lut1dSize, lut3dSize, lut1dArrays, lut3dArray[Byte])
                → LutsRepository.insertLuts (Room)
                → SettingsManager.setLut / setRecordLut / setLutDisplayState
                → GPU 上屏(androidx.media3.effect.ColorLut / SingleColorLut)
```

native 符号仅两个,干净:

```
Java_com_blackmagicdesign_android_utils_luts_NativeLutParser_parseCubeFile
LUT_3D_INPUT_RANGE_R / _G / _B        ← 支持 .cube DOMAIN_MIN/MAX 变体
```

`.cube` 的 `LUT_3D_INPUT_RANGE` 被识别,说明解析器兼容非 [0,1] 输入域的 LUT,导入第三方 LUT(如 Resolve 导出的 Log 域 LUT)时可以直接用。

## 8. 可玩点 / 攻击面清单

1. **改包改名** — `string/app_name` 单点可改,无需动 DEX(见 §9)。
2. **签名校验很薄** — 全 APK 仅 1 处 `getPackageInfo` + 2 处 `signatures` 字符串,无 Frida/Xposed/root 检测字符串(`frida`/`xposed`/`ptrace`/`magisk` 全零命中)。这意味着**二次改包后的完整性风险主要来自用户侧,而不是 App 自检**。
3. **云账号面** — OAuth + MFA + OTP,凭证走 `AuthenticationManager`;token 生命周期集中在 `cloud/manager`。抓包即可看清全部流程(`okhttp3` 未做证书固定特征——样本里只有系统 CA + 内置 `assets/ssl/ca-certificates.crt`,属常规轮子)。
4. **相机控制** — `bmd.cam_app_control.v5` 全字段公开,可自建遥控端。
5. **Insta360 集成** — 793 类 + BLE 遥控通道,是额外攻击面(蓝牙配对、固件升级 `sdkcamera.upgrade.FwUpgradeManager`)。
6. **推流** — GStreamer + `davstream`,RTMP/WHIP 端点通过 `ApiStreamRouterEndpoint` 下发。

## 9. 复现:解包 → 改标签 → 重签 → 装

```powershell
$W = "D:\pojia\mediastorm_re"
$BT = "D:\XuanJianDev\AndroidSdk\build-tools\36.1.0"

# 0) 取 apktool(本机 tools\ 里的 jar 下载不完整时按此拉取)
curl -L -o "$W\tools\apktool.jar" `
  "https://github.com/iBotPeaches/Apktool/releases/download/v2.11.1/apktool_2.11.1.jar"
java -jar "$W\tools\apktool.jar" --version

# 1) 反编译(apktool 2.11.1)
java -jar "$W\tools\apktool.jar" d "$W\samples\ms_camera.apk" -o "$W\apktool_out" -f

# 2) 改应用名
#    apktool_out\res\values\strings.xml        -> <string name="app_name">自定义名字</string>
#    apktool_out\res\values-zh\strings.xml    -> 同上
#    需要换图标:替换 res\mipmap-*\ic_launcher.webp 与 ic_launcher_foreground.webp

# 3) 重新打包
java -jar "$W\tools\apktool.jar" b "$W\apktool_out" -o "$W\out\patched_unsigned.apk"

# 4) 生成 keystore + 对齐 + v3 签名
& "$BT\zipalign.exe" -p -f 4 "$W\out\patched_unsigned.apk" "$W\out\patched_aligned.apk"
keytool -genkeypair -keystore "$W\out\re.keystore" -alias re -keyalg RSA -keysize 2048 `
        -validity 10000 -storepass 123456 -keypass 123456 -dname "CN=re, O=lab, C=CN"
& "$BT\apksigner.bat" sign --ks "$W\out\re.keystore" --ks-pass pass:123456 `
        --v3-signing-enabled true --v1-signing-enabled false `
        --out "$W\out\patched_signed.apk" "$W\out\patched_aligned.apk"

# 5) 验签 + 装机
& "$BT\apksigner.bat" verify --print-certs "$W\out\patched_signed.apk"
adb install -r "$W\out\patched_signed.apk"
```

> 注意:改了签名就和原包不兼容,必须先卸载旧包(`adb uninstall com.blackmagicdesign.android.blackmagiccam`),数据目录一并清空。
